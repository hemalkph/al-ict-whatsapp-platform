The production worker commands are:

```sh
node --env-file-if-exists=.env.local --import tsx scripts/bots-worker.ts
node --env-file-if-exists=.env.local --import tsx scripts/whatsapp-worker.ts
node --env-file-if-exists=.env.local --import tsx scripts/whatsapp-outbound-worker.ts
```

Run directly from the repository root under the future supervisor. Package commands are convenient locally; supervising `npm` adds an unvalidated signal boundary. See [deployment guidance](DEPLOYMENT.md#worker-shutdown-reliability-checkpoint) and [testing instructions](TESTING_STRATEGY.md#worker-shutdown-reliability-checkpoint-2026-11-10).

All unsuccessful attempts remain part of the record:

- Initial launcher diagnostic failed before execution because a temporary `.ts` file used top-level await under CJS; changing only its temporary extension to `.mts` resolved it. The first CLI launch under the sandbox failed to create tsx's local IPC socket (`EPERM`); the authorized local comparison then ran outside that restriction.
- Initial full unit run: **34 failed, 2,881 passed, 30 errors** across 122 files. Four failures were exact structural inventories affected by the intended launcher/dependency/test-fixture changes; the other 30 failures and 30 errors came from local HTTP/TLS sockets denied by the sandbox. A later focused run retained **1 failed, 254 passed** until the exact dev-dependency count was updated for the tsx move. No exit-code assertion was relaxed. Both subsequent unrestricted full unit runs passed (2,916 and final 2,918).
- Initial typecheck found two nullable piped stream references in the new process helper; the next found a duplicate signal property in the study record. Both were corrected, retaining the actual terminating signal and separately named sent signal. Earlier study records still retain their sent signal in the `signals` array.
- The first external DB diagnostic runner stopped at its refusal self-check before connecting: a string replacement changed the wrong part of a synthetic URL. A URL pathname assignment fixed the self-check; the existing harness was unchanged. Subsequent guarded executions passed.
- Two offline lockfile-generation attempts failed on the sandboxed default npm cache and an uncached optional platform tarball. The narrow dependency move and existing production flags were updated without changing package versions/integrities and validated with npm's production dependency tree. A fresh deployment installation was not claimed.
- Initial format check identified five modified files; formatting was applied. The first launcher observer registered `close`, which the wrapper exits too early to emit; an additional `exit`/kill observer captured the application's actual SIGKILL. Both attempts are retained.

- On resume, the final read-only database preservation recheck found the approved container in `exited` state. The guard refused before creating any database client. Completed DB runs remain valid historical evidence; no new DB run or post-resume session inspection was performed.
