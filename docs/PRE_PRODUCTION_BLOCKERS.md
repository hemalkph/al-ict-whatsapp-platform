# Pre-production blocker register

What Phase 03 (authentication, memberships, authorization, staff management, browser E2E) knowingly does **not** solve. Green unit, database and browser suites do not close any of these. Each needs an owner and a decision before real users or real WhatsApp traffic are involved.

| #   | Blocker                                                                                    | State today                                                                                                                                                                                                                                                                                                                         | Needed before production                                                                                                                                                                                                                                                                                                                                            |
| --- | ------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Trustworthy production client-IP propagation                                               | The database rate limiter keys on the IP Better Auth derives from `x-forwarded-for`, and Next adds that header from the socket address when it is absent. Behind a proxy or CDN the value is whatever the edge forwards, and a client may supply its own. The browser E2E proves the limiter is wired in; it cannot prove IP trust. | Decide the topology, configure the trusted proxy header(s) explicitly (Better Auth `advanced.ipAddress.ipAddressHeaders` and `trustedProxies`, verified in the installed version) so only the edge-set value is used, strip client-supplied forwarding headers at the edge, and test it. Until then limiter keys can be spoofed or collapse onto the proxy address. |
| 2   | WAF / platform rate limiting                                                               | Only the in-app database limiter exists, and only on Better Auth's HTTP endpoints (server-side `auth.api` calls bypass it).                                                                                                                                                                                                         | Platform or WAF limits in front of `/api/auth/*`, `/api/account/*` and `/api/staff/*`, with per-IP and global ceilings.                                                                                                                                                                                                                                             |
| 3   | Rate limiting and hardening of authenticated password-change and password-reset routes     | `/api/account/change-password` and `/api/staff/*/reset-password` have no limiter of their own; they need a valid session (and `staff.manage` for resets) but a stolen session could guess the current password at full speed.                                                                                                       | A per-user (not only per-IP) limiter or lockout on current-password verification, and a decision on re-authentication ("fresh session") for administrator resets.                                                                                                                                                                                                   |
| 4   | Four moderate `npm audit --omit=dev` findings (`drizzle-kit` / `@esbuild-kit` / `esbuild`) | Reported through `better-auth`'s optional `drizzle-kit` peer. Dev-time tooling only, not in the runtime bundle. Documented, not forced: `npm audit fix --force` is not acceptable.                                                                                                                                                  | Re-check on each dependency update; resolve when a compatible `drizzle-kit` / `better-auth` release removes the old esbuild, or record an accepted-risk decision.                                                                                                                                                                                                   |
| 5   | Multi-organization selector                                                                | One ACTIVE membership is used implicitly; zero is 403 and more than one is 409. Staff creation refuses existing identities, and administrators cannot reset or revoke shared identities.                                                                                                                                            | Only if multi-organization operation is enabled: the slug-in-route selector, an invitation flow the user accepts while authenticated, and platform-level handling for shared identities (ADR 0012).                                                                                                                                                                 |
| 6   | Stale provisioning-intent monitoring                                                       | `staff_provisioning_intents` never expire automatically (releasing one could let another organization claim a partial identity). A recovery CLI exists (`auth:intents`); nothing alerts when an intent is stuck.                                                                                                                    | A scheduled check or alert on intents older than a threshold, and an on-call runbook step (`docs/RUNBOOK_AUTH.md`).                                                                                                                                                                                                                                                 |
| 7   | Email / self-service password recovery                                                     | No email infrastructure. The public reset surface is closed. Recovery is an administrator reset (exclusive identities only) or the operator CLI.                                                                                                                                                                                    | When email exists: verified, rate-limited self-service reset and email verification, designed with the shared-identity rules in ADR 0012.                                                                                                                                                                                                                           |

## Also still open (lower severity, documented elsewhere)

- Intent-recovery clock-skew tolerance is 5 s (`CLOCK_SKEW_TOLERANCE_MS`), a tripwire rather than the primary ownership guard.
- RLS is deferred (ADR 0012, RLS decision); runtime/migration database role split belongs to the deployment milestone.
- Absolute session cap (beyond the 7-day sliding window) was left undecided.

## Phase 04 (WhatsApp webhooks): open items recorded at checkpoint 1

| #   | Blocker                                                  | State today                                                                                                                                                                                                                                          | Needed before production                                                                                                                                                                                                                                                                                   |
| --- | -------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 8   | Identity-change delivery unresolved (G0 item H1)         | Official Meta pages contradict each other (a system message with only the new BSUID versus a separate `user_id_update` field versus a legacy `user_changed_number` page). The handler is **not designed**; no automatic `wa_id` mutation is allowed. | Confirm in the real App Dashboard which fields are subscribable and observe a real identity change; then design the handler. Until then late events under a retired BSUID resolve through `contact_bsuids`, but a rotated user may appear as a new contact.                                                |
| 9   | Raw webhook body retention                               | `webhook_requests.raw_body` stores exact bytes with personal data; no retention job exists.                                                                                                                                                          | Decide retention (and held-event exemption), build the job, and handle the Phase 02 `NO ACTION` provenance FKs (confirmed by test: deleting an event is blocked until `messages.source_webhook_event_id` and `message_status_events.webhook_event_id` are nulled first; `contact_bsuids` is not affected). |
| 10  | Wire form of non-ASCII webhook bodies unconfirmed        | The signature rule is exact received bytes only. Whether Meta sends literal UTF-8 or `\uXXXX` escapes is unverified.                                                                                                                                 | One live delivery with Sinhala/Tamil text (optional live smoke). A failure there is a transport investigation; the rule is never loosened.                                                                                                                                                                 |
| 11  | BSUID portfolio invariant is documentation only          | One organization must equal one Meta Business Portfolio. Not verifiable without an authenticated Graph call.                                                                                                                                         | Operator confirmation at onboarding; schema change (`business_portfolio_id`) if an organization ever spans portfolios. Re-check whether old and new BSUIDs can be valid together (H2) before adding a current-alias unique index.                                                                          |
| 12  | Media ids from webhooks expire after 7 days              | `message_attachments` rows stay `PENDING`; no downloader exists in Phase 04.                                                                                                                                                                         | A downloader that runs promptly, handles `EXPIRED`, and uses the access token (outbound/media phase).                                                                                                                                                                                                      |
| 13  | Webhook endpoint abuse and log flooding                  | Invalid signatures are rejected without a database write, but each is a log line.                                                                                                                                                                    | Platform/WAF limits in front of `/api/webhooks/whatsapp` (extends item 2).                                                                                                                                                                                                                                 |
| 14  | Contact merge tooling                                    | Conflicting identities fail closed and are flagged; nothing merges two contacts.                                                                                                                                                                     | Operator merge tooling before relying on identity conflicts being rare.                                                                                                                                                                                                                                    |
| 15  | Reaction versus the customer-service window unresolved   | Meta's window text mentions messages and calls only. Reactions never extend `last_inbound_at` (conservative).                                                                                                                                        | Confirm against Meta's current documentation or behavior before the compliance guard is built.                                                                                                                                                                                                             |
| 16  | BSUID aliases can be re-pointed by an UPDATE             | `UNIQUE (organization_id, bsuid)` blocks a second alias row but not an `UPDATE ... SET contact_id` to another contact of the same organization (tested and recorded as a finding).                                                                   | The resolver must never re-point an alias and must fail closed on conflicts; consider an immutability trigger once the resolver exists.                                                                                                                                                                    |
| 17  | Migration 0002 must precede any webhook data             | `ADD COLUMN raw_body bytea NOT NULL` (no default, no backfill) fails safely if `webhook_requests` already holds a row; proven with the real migrator.                                                                                                | Deploy order: apply 0002, then the webhook route. If data could already exist, stop and decide its fate (export as evidence; never fabricate wire bytes from jsonb).                                                                                                                                       |
| 18  | Stored webhook events are not processed yet              | Ingress stores deliveries and per-item events (PENDING / held / ignored / dead) but no worker, requeue operation or domain handler exists. Held (`UNROUTABLE`) and ignored events, including every `system` message, wait for them.                  | Worker, requeue/activation operations and handlers (later Phase 04 checkpoints); retention must exempt held events.                                                                                                                                                                                        |
| 19  | Public webhook endpoint hardening beyond the application | The endpoint refuses oversize bodies (4 MiB, connection closed) and unverified deliveries without writing, but still reads up to 4 MiB per request before verifying the signature.                                                                   | Platform/WAF rate and size limits in front of `/api/webhooks/whatsapp` (extends items 2 and 13); trusted-proxy handling.                                                                                                                                                                                   |
